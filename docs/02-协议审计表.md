# 02 · 开源协议审计表

> 目的：保证「优先复用开源」的同时 100% 协议合规。任何新资源接入前必须过本流程。

## §1 审计规则（必须全部满足）

1. 仓库必须带 LICENSE 或明确声明协议；无 LICENSE 的一律**不接入**（可作算法参考）。
2. 允许协议：MIT / Apache-2.0 / GPL-3.0（or-later） / BSD-2/3-Clause / CC0 / Unlicense。
3. 拒绝：CC-BY-NC\*（非商用）、CC-BY-ND、AGPL（网络传染）、自定义模糊协议。
4. 防广告污染：clone 后先 `grep -ri "admob\|穿山甲\|unityads\|gdpr\|pangle\|applovin" <src>`，命中即弃用。
5. GPL 系资源**复制代码**时必须保证本项目整体 GPL（本项目即为 GPL-3.0-or-later，✅ 已满足）。
6. 接入后立即登记 THIRD_PARTY_NOTICES.md：来源、协议、**改动清单**（我们对字体/按钮/去广告的每处修改）。
7. 素材（音效/图标）：优先 CC0（Kenney、OpenGameArt CC0 区）；自绘矢量为主。

## §3 审计工作流（新游戏接入 SOP）

```
选型（开源可得性打分）
  → 协议初筛（§1.1-1.3）
  → clone 防广告 grep（§1.4）
  → 本地试运行（手机 WebView / 原生可编译）
  → 接入 + 老年化改动（CSS 注入/字号/按钮）
  → 登记 THIRD_PARTY_NOTICES.md（含改动清单）
  → 本表更新状态：待核实 → 已接入/仅参考/弃用（注明原因）
```

## §4 已知风险备忘

- GitHub 直连在本机不通：拉取用镜像 `https://gh-proxy.com/https://github.com/...`（M0 已验证 zip 下载与 git clone 均可用）。
- 「无 LICENSE」不等于「免费」：版权默认保留，务必按 §1.1 处理。
- 后续若引入 GPL 系 H5 游戏整包分发，确保不引入 AGPL/带网络服务条款的变体。
